# Safari Web Extensions: documented facts for porting CC Checker (Chrome MV3)

Research date: 17 October 2026. Read-only research; nothing in the repository was changed.

Scope as briefed: toolbar click → `initChecker` → content script appends an extension-page iframe (`index.html`) at the foot of the page; eyedropper calls `chrome.tabs.captureVisibleTab` from the service worker; the service worker relays every message; copying uses `document.execCommand('copy')` in the cross-origin iframe; only permission is `activeTab`; content script is declared for `<all_urls>`, top frame only (`public/manifest.json`, `public/app/content.js`, `public/app/background.js`, `docs/ARCHITECTURE.md` §Safari and other browsers).

How to read the tables. **Quote** = verbatim, under 15 words, in quotation marks. **Paraphrase** = marked "(paraphrase)". **Code** = a fact read from WebKit's open-source implementation (`raw.githubusercontent.com/WebKit/WebKit/main/…`), which is primary for WebKit but is *not* a statement about the Safari app layer: Safari's own host code (the `WKWebExtensionController` delegate) is closed, so anything that depends on delegate behaviour is marked accordingly. Status: VERIFIED (primary source read and quoted), UNVERIFIED (not found in a primary source, or only secondary), SOURCES DISAGREE (two primary sources conflict; both quoted).

Apple's developer documentation is a JavaScript app; `WebFetch` returns only the page title. Every Apple page below was read via its Markdown endpoint (`https://developer.apple.com/documentation/safariservices/<slug>.md`) with `curl`, and the quotes are from that text. MDN's compat tables are not in MDN's HTML either; they were read from the `mdn/browser-compat-data` JSON on GitHub (BCD, cited per file).

Design implication (not a sourced claim): with `<all_urls>` content scripts and only `activeTab`, Safari will badge the icon on *every* site until the user picks "all websites", and the content script is injected only after the grant. For CC Checker's "click → inject" flow, the first click on a new site becomes the grant interaction, and the content script is injected afterwards without a page reload only if Safari injects into already-loaded pages (WWDC20 says it does, hence the DOMContentLoaded warning). The `initChecker` message sent in the same click handler may arrive before the content script exists; this must be tested (Open points).

## Open points

1. **First-click race.** With `<all_urls>` content scripts and `activeTab`, the first toolbar click on an un-granted site is itself the grant. Whether the content script is injected into the already-loaded page in time to receive `initChecker` from the same click, or whether `tabs.sendMessage` fails (CC Checker then shows the error popup), must be tested in Safari. WWDC20 implies late injection happens; timing relative to the message is undocumented.
2. **`activeTab`-only vs badge nag.** Safari badges the icon on every new site until "all websites" is chosen. Decide whether to drop the `<all_urls>` static content script in favour of `scripting.executeScript` on click (needs `scripting` permission; Safari 15.4+), which fits Safari's `activeTab` model and removes the badge.
3. **Clipboard in the extension iframe.** WebKit gates `execCommand('copy')` and `writeText` only on user gesture/transient activation and ignores `clipboard-write`; whether `safari-web-extension://` iframes are secure contexts and whether the gesture propagates into the iframe's click handler is untested here.
4. **`captureVisibleTab` on iOS** has unresolved cropping/scale reports (iOS 16–17) and an unverified failure on extension-origin pages; `devicePixelRatio` mapping in `content.js` will need re-measuring.
5. **Per-launch UUID.** Verify in current Safari that the origin changes per launch (WWDC20) and that nothing (localStorage keys are inside the extension origin and WebKit migrates them) depends on a stable origin.
6. **`action.openPopup`** is supported from Safari 16 (the repo's `docs/ARCHITECTURE.md` says the opposite). Test `setPopup({popup: ''})` reset semantics; `null` is accepted from Safari 18.
7. **Xcode floor and CI.** Apple's pages give no minimum Xcode; `xcrun safari-web-extension-packager` on a GitHub `macos-15` runner (Xcode 16.4 default) is untried. Decide between the CLI packager with in-place references (keeps `build/` as the source) and the App Store Connect web packager.
8. **Containing-app review.** Guideline 4.4 wants "some functionality … where possible"; whether the template's default enable screen suffices for an extension-only app is not stated.
9. **iOS UI labelling** ("aA"/Page menu vs "More"/"Action" menu) and exact permission-prompt labels differ between Apple pages; confirm on device for user-facing docs.
10. **Secondary-only items** (forum threads 744718/699803, WebKit bugs 261716/267823) were summarised by search, not read; read them before citing in the research file.
