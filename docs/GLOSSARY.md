# Glossary

Ubiquitous language for the Colour Contrast Checker extension. Use these terms consistently in code
comments, commit messages, `PROGRESS.md` entries, review findings and agent prompts.

Shape adapted from the `GLOSSARY.md` in nas-stacks and moe — category-grouped term tables, each
entry pointing at the file that is authoritative for it. **The terms themselves are not a port.**
Those repos describe Compose stacks, watchdogs, boards and personas, none of which exist here. What
follows is this repo's own vocabulary, read out of `public/app/content.js`, `public/app/background.js`,
`src/context.tsx`, `src/utils/color-utils.ts` and the docs in `docs/`, not invented for the occasion.

**Where a definition was corrected, the correction is kept** — superseded text stays as
~~strikethrough~~ next to what replaced it, with the date. **Where something is defined but not yet
observed working, the entry says so.** A green build on the author's Mac was not evidence for a
case-sensitive checkout on 4 September 2026, and the same applies to prose about the system.

Last reviewed: 11 September 2026.

## Extension

The three execution contexts and the messages between them. Fuller treatment, with the sequence of
a pick end to end, in `docs/ARCHITECTURE.md`.

| Term                               | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Content script**                 | `public/app/content.js`. Plain, unbundled JS that Chrome injects into every `<all_urls>` page at `document_idle` and copies verbatim to `build/` — Vite and `tsc` never see it. It hosts the panel and the loupe and runs only in the top frame (`window.self === window.top`): on 4 September 2026 `all_frames: true` plus tab-addressed messages injected a full checker into every embedded iframe, so the guard was added and the manifest entry removed.                                                            |
| **Service worker**                 | `public/app/background.js`. The MV3 background script: handles the toolbar click (`chrome.action.onClicked`), decides restricted-page versus `initChecker`, and relays every message between the content script and the extension page. Relayed `tabs.sendMessage` calls go through `sendToTab`, the promise form with `.catch(() => undefined)`, because a tab that navigated or closed is not an error worth surfacing; the `initChecker` send is the exception — it is awaited so a failure can show the error popup. |
| **Extension page**                 | `index.html` → `src/index.tsx`, the React app, served from the `chrome-extension://<id>/` origin. It is the only thing Vite builds. It talks to the service worker with `chrome.runtime.sendMessage` and never to the content script directly.                                                                                                                                                                                                                                                                           |
| **Panel / iframe**                 | The `<iframe data-cc-checker>` the content script appends to `document.body`: fixed, full width, `IFRAME_HEIGHT` (475px) tall, maximum z-index, `src = chrome.runtime.getURL('index.html')`. A `<style data-cc-styles>` adds 475px of bottom padding to the host page so the panel covers nothing. The 475px is deliberately unchanged.                                                                                                                                                                                  |
| **activeTab**                      | The extension's only permission (`public/manifest.json`). It is granted by a real toolbar click on that tab and is the only thing that makes `captureVisibleTab` legal. Deliberately not widened to `host_permissions`; a diff that does so is BLOCKING in `docs/DA-REVIEW.md` until the PR body argues for it.                                                                                                                                                                                                          |
| **captureVisibleTab**              | `chrome.tabs.captureVisibleTab(sender.tab.windowId, { format: 'png' })` in the service worker — the screenshot the loupe samples from. Because it needs the `activeTab` grant, Playwright (which cannot click the toolbar) runs the picker tests from a manifest copy with `host_permissions: ["<all_urls>"]`; `docs/TESTING.md` explains why that is honest.                                                                                                                                                            |
| **web_accessible_resources (WAR)** | The manifest list of files a web page may load from the extension: only `index.html` and `fonts/avenir-next-variable.woff2`, matched to `<all_urls>`. The page's own subresources (`/assets/*`, `/images/*`, favicons) load from the static extension origin and need no entry — verified with HTTP 200s inside the iframe on 4 September 2026. Widening the list is BLOCKING in `docs/DA-REVIEW.md`.                                                                                                                    |
| **Dynamic URL**                    | `use_dynamic_url: true` on the WAR entry: `chrome.runtime.getURL('index.html')` in the content script yields a per-session GUID origin rather than the stable extension id, so a page cannot fingerprint the extension by probing its URL. Chromium-only — one of the known gaps for Safari (`docs/ARCHITECTURE.md` §Safari and other browsers).                                                                                                                                                                         |
| **Restricted page**                | A tab the content script cannot run in: `chrome://`, `chrome-extension://`, `edge://`, `about:`, `data:`, `file://`, `view-source:`, the Chrome Web Store, Edge Add-ons, or a tab with no URL (`RESTRICTED_URL_PATTERNS` in `background.js`). A tab opened before install or update behaves the same way because no listener is there yet; reloading the page fixes it.                                                                                                                                                  |
| **Error popup**                    | `public/error.html`, shown by `showErrorPopup(tabId)` when the page is restricted or `initChecker` cannot be delivered. It is bound as the popup **for that tab only**, the unbind is scheduled 500ms later **before** `chrome.action.openPopup()` is tried, and `openPopup` is `typeof`-guarded. Order matters: on 4 September 2026 a sync TypeError from a missing `openPopup` could strand `error.html` as the permanent popup. Not covered by e2e.                                                                   |
| **Loupe / eyedropper**             | The hidden `<div data-cc-canvas-wrapper>` holding an 8×8 `<canvas>` (`LOUPE_SIZE`) in the content script. While picking it follows the mouse with the cursor hidden, drawing an 8×8 sample of the screenshot scaled by `devicePixelRatio` (read on every move, because page zoom can change); a click reads pixel (3,3). Scroll and resize hide it after a 66ms settle and request a fresh screenshot 66ms after that.                                                                                                   |
| **`initChecker`**                  | Service worker → content script, on a toolbar click against an unrestricted tab. Appends the iframe, style and loupe; a no-op if `[data-cc-checker]` already exists.                                                                                                                                                                                                                                                                                                                                                     |
| **`getScreenshot`**                | Extension page → service worker, `{ type, key }` where `key` is `'background'` or `'foreground'`. The worker captures the tab and forwards `{ type, key, data }` to the content script, which shows the loupe and attaches its listeners.                                                                                                                                                                                                                                                                                |
| **`updateScreenShot`**             | Content script → service worker after a scroll or resize; the worker captures again and forwards the new data URL, and the content script swaps the loupe image without re-attaching listeners.                                                                                                                                                                                                                                                                                                                          |
| **`colorPicked`**                  | Content script → service worker → extension page, `{ type, key, rgb }`. Relayed rather than delivered directly so the iframe also receives it in incognito windows. `src/context.tsx` handles only the relay (`sender.tab` undefined); the content script's direct broadcast also arrives and is ignored — until 4 September 2026 every pick was handled twice.                                                                                                                                                          |
| **`closeColorPicker`**             | Extension page → service worker → content script, sent after a pick lands. Removes the mousemove, scroll, resize and click listeners, clears the pending screenshot timer and restores the cursor.                                                                                                                                                                                                                                                                                                                       |
| **`closeChecker`**                 | Extension page → service worker → content script, from the panel's close button. Tears the picker down **first**, then removes iframe, style and loupe. On 4 September 2026 the reverse order left scroll listeners live, so the next scroll requested a screenshot and the loupe reappeared with nothing to dismiss it.                                                                                                                                                                                                 |

## Colour

Everything derives from two HSL tuples in `src/context.tsx`; contrast and grades are recomputed on
every render, never stored.

| Term                   | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`ColorTuple`**       | `[number, number, number]` in `src/global-types.ts`. Used for both HSL and RGB triples (`hslToRgb` returns one, `TPickedColor.rgb` is one); which it is depends on the function, so read the signature.                                                                                                                                                                                                                                                       |
| **HSL tuple**          | A `ColorTuple` read as `[h, s, l]` with `h` in degrees and `s`, `l` in 0–1 — chroma-js's `hsl()` shape. The `background` and `foreground` state, and the `background` / `foreground` localStorage keys, are HSL tuples serialised with `JSON.stringify`.                                                                                                                                                                                                      |
| **Hue normalisation**  | `toHslTuple` in `src/utils/color-utils.ts` replaces a non-finite hue with 0 wherever a tuple is created; `readStoredColor` in `src/context.tsx` does the same for a stored `null`. chroma returns `NaN` for a grey's hue, JSON turns `NaN` into `null`, and on 4 September 2026 an effect was patching the result back into state in place — saturating a grey gave `#111111` instead of `#331111`. Sanitise at the boundary; never patch state in an effect. |
| **Contrast ratio**     | `chroma.contrast(bg, fg)` via `getContrast` in `color-utils.ts`, the WCAG 2 luminance ratio from 1 to 21. Displayed to two decimals by the `ratio` atom (`toFixed(2)`); the local `roundTo` in `color-utils.ts`, which replaced `lodash.round` on 4 September 2026, rounds the slider labels in `color-control` instead.                                                                                                                                      |
| **WCAG grades**        | `getLevel(contrast)` in `color-utils.ts` returns `TLevels` — `AALarge`, `AA`, `AAALarge`, `AAA`, each `'Pass'` or `'Fail'`. Thresholds are inclusive, as WCAG's "at least" requires: `>= 7` passes all four; `>= 4.5` passes AA, AA Large and AAA Large; `>= 3` passes AA Large only; anything else fails everything. They were strict `>` until 18 September 2026 — exactly 4.5 failed AA — which no 8-bit pair could reach.                                 |
| **Poor contrast**      | `isPoorContrast = contrast < 3` in `src/context.tsx`. Below it the UI stops rendering text and controls in the foreground colour and switches to black or white, chosen by `isBackgroundDark`, so the checker itself stays readable on a failing pair.                                                                                                                                                                                                        |
| **`isBackgroundDark`** | `isDark(background)` — the background's CIE `lab.l` is below 60 (`color-utils.ts`). Drives the black-or-white fallback above and the `badgeDark`-style variants in the CSS Modules.                                                                                                                                                                                                                                                                           |
| **Saved colours**      | The `colors` localStorage key: an array of `{ background, foreground }` hex pairs, newest first, capped at `MAX_SAVED_COLORS` (5), with an exact-pair duplicate ignored. Rendered by the `saved-colors` molecule as a `<ul>` of `<li>` swatches — the `<li>` was missing until 4 September 2026.                                                                                                                                                              |
| **Defaults**           | `DEFAULT_BACKGROUND = '#ffe66d'` and `DEFAULT_FOREGROUND = '#222222'`, exported from `src/context.tsx`. They must match `--background-color` / `--foreground-color` in `src/styles/globals.css`; the two homes are listed in `docs/DEVELOPMENT.md` §State-surface ownership; the first-run e2e test compares `input#background` with the body's `--background-color`, which `context.tsx` has already overwritten, so it does not prove the two files agree.  |
| **Share URL**          | `https://colourcontrast.cc/?background=<hex>&foreground=<hex>` (hex without `#`), built in `src/components/02-molecules/actions/actions.tsx` and copied by `CopyCta`. It links to the sibling Remix web app `Pushedskydiver/Colour-Contrast-Checker`, which shares domain logic with this repo but no code.                                                                                                                                                   |

## Code

Conventions in full: `docs/CONVENTIONS.md`. The gates and how to run them: `docs/DEVELOPMENT.md`.

| Term                        | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Atomic tiers**            | `src/components/01-atoms`, `02-molecules`, `03-organisms`, `04-layouts` — numbered so the order is visible in a listing. Imports point down or sideways, never up; an organism's sub-components live in its own `components/` directory (`tabbed/components/tab.tsx`). Directory and file names are kebab-case, and case is load-bearing: on 4 September 2026 the git index still tracked `01-Atoms/` and a Linux clone could not build.                                           |
| **CSS Modules**             | A component directory holds `<name>.tsx` and `<name>.module.css` (`color-picker-cta` and `tabbed/components/` have no stylesheet of their own), classes camelCase (`.badgeDark`) because `text.tsx` builds names like ``styles[`${size}Text`]``. Cross-file `composes: container from containers` is why `npm run build` prints the benign `A PostCSS plugin did not pass the 'from' option`.                                                                                      |
| **`@value` tokens**         | CSS Modules constants. Breakpoints live once in `src/styles/modules/breakpoints.module.css` (`@value --bp-medium: 768px;`), are imported per module (`@value --bp-medium from --breakpoints;`) and used with range syntax (`@media (width >= --bp-medium)`). Stylelint allows the at-rule for this reason.                                                                                                                                                                         |
| **`~` alias**               | `~/` → `src/`, declared in `vite.config.ts` (`resolve.alias`), `vitest.config.ts` and `tsconfig.json` (`paths`). Use it for anything that crosses a directory; stay relative for the same directory or a sibling in the same tier. Both forms exist today — do not convert existing imports. `public/app/*.js` cannot use it.                                                                                                                                                      |
| **TS 7 native vs TS 6 API** | `lint:ts` runs TypeScript 7.0.2's Go `tsc`, installed as `@typescript/native`. The bare `typescript` name resolves to `@typescript/typescript6` (bin `tsc6`) purely so `typescript-eslint` has a JS API. This is the TypeScript team's documented side-by-side layout; do not "tidy" the two into one package.                                                                                                                                                                     |
| **Gates**                   | The checks that fail rather than advise: `npm run lint` (tsc on both tsconfigs, ESLint, Stylelint, `prettier --check`), `npm run test:unit` (22 Vitest cases), `npm run build`, and the 20-test Playwright suite. The CI job `quality` in `.github/workflows/ci.yml` runs the same set on `ubuntu-latest` and is the only thing that proves a case-sensitive checkout. It has been a required status check on `main` since 11 September 2026, after its first green run on PR #28. |
| **Pre-push suite**          | `npm run lint && npm run test:unit && npm run build && npm run test:e2e`, green before every push. `npm test` is build plus e2e; `test:e2e` alone assumes `build/` is current. `npx playwright install chromium` once per machine, and again after a `@playwright/test` bump — the pinned Chromium moves with the package.                                                                                                                                                         |

## Review vocabulary

Sequenced in `docs/DEVELOPMENT.md` §The review gate; the grep-able trigger table is in `CLAUDE.md`.

| Term                                | Definition                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **DA review**                       | Devil's-advocate review: a subagent (`.claude/agents/da-review.md`) dispatched from a fresh context, never the writer's own, walking the checklist in `docs/DA-REVIEW.md`. Mandatory for `src/**`, `public/app/**` and `public/manifest.json` (the manifest is reviewed by both agents). Findings are returned in-chat, never posted on the PR.                                                               |
| **Self-review**                     | Walking `docs/SELF-REVIEW.md` against `git diff main...HEAD` yourself, **after** DA and never in parallel, because DA-driven fixes introduce fresh line-level slips that an earlier self-review cannot have seen.                                                                                                                                                                                             |
| **copilot-surrogate**               | The factual-claim reviewer (`.claude/agents/copilot-surrogate.md`). Reads every touched file at HEAD in full — not the diff — and grep-falsifies each checkable claim. Mandatory for `docs/**`, `CLAUDE.md`, `.claude/agents/**`, `README.md`, manifest or config changes, and any diff over 200 lines excluding `package-lock.json`.                                                                         |
| **spec-grill**                      | Two-phase adversarial review of a spec or plan (`.claude/agents/spec-grill.md`) run **before** code moves against it, so the plan is stress-tested rather than the implementation of a flawed one.                                                                                                                                                                                                            |
| **Discovery vs verification round** | Two different questions. Discovery rounds (R1…R*n-1*) ask "find what is wrong" and iterate until findings converge to nits; the verification round (R*n*, exactly one, a distinct prompt) asks "confirm or disprove that this is at the nit-floor". Finders and verifiers are separate fresh agents; default cap two rounds, then a manual pass.                                                              |
| **Nit-floor**                       | The point where successive rounds produce only cosmetic deltas, confirmed by a verification round returning zero — never by a discovery round. Report "nit-floor reached" honestly; on 4 September 2026 a 139-agent audit exhausted the session budget twice on a ~3.7k-LOC repo after five finders plus hands-on reproduction had already found everything that mattered. More verifiers is not more rigour. |
| **BLOCKING / MATERIAL / LOW**       | The severity labels in `docs/DA-REVIEW.md`. BLOCKING cannot land (a widened permission or WAR entry, a message with no receiver, a case-only path mismatch, a false verification claim, an accessibility regression). MATERIAL must be fixed before proceeding. LOW may be deferred with a written reason; "we'll fix it later" is not one.                                                                   |
| **Blast-radius doc**                | A file whose edit changes behaviour or policy well beyond its diff, so it needs a PR of any size and Alex's reading of the substance: `CLAUDE.md` (and the `AGENTS.md` symlink), `docs/**`, `.claude/agents/**`, `public/manifest.json`, `.github/workflows/**`. The list in `docs/GIT.md` §Blast-radius docs is the source of truth.                                                                         |
| **NOTICED BUT NOT TOUCHING**        | The self-review discipline of listing an out-of-scope improvement instead of fixing it inline, then offering to add it to `PROGRESS.md` (`docs/SELF-REVIEW.md`). Drive-by fixes in `public/app/content.js` are especially expensive because it runs in every page the user opens.                                                                                                                             |

## Process

| Term                    | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`PROGRESS.md`**       | The living state document at the repo root: what merged, what was uploaded to the store (different things — say both), the branch and what remains, and a pointer-only "next session loading instructions" block. Read first at session start.                                                                                                                                                                                                                                               |
| **`SESSIONS.md`**       | `docs/history/SESSIONS.md`, the archive. When `PROGRESS.md`'s detail band holds more than five sessions or roughly 10k tokens, the oldest entry compresses to a one-line row here; the full text survives in `git log -p PROGRESS.md`. Session 1 was the first to archive out, on 13 September 2026.                                                                                                                                                                                         |
| **Session handoff**     | Updating `PROGRESS.md` and archiving overflow at the sooner of: context nearing the compaction budget, a natural boundary (PR merged, workstream segment done, release uploaded), or the compaction warning. Hand off before the warning — quality slips well before context fills. Mechanics: `docs/DEVELOPMENT.md` §Session handoff.                                                                                                                                                       |
| **Promotion ladder**    | Observation → Recorded (`PROGRESS.md`, `docs/REVIEW-PATTERNS.md`) → Promoted (a rule in `CLAUDE.md` or `docs/*.md`) → Gated (`ci.yml` or a lint rule). A practice becomes a rule after firing twice; a rule becomes a gate when reader discipline has demonstrably failed to hold it. Both 4 September 2026 examples are gates: the case-sensitivity incident is held by `quality` on Linux, the effect-mutates-state class by `react-hooks/set-state-in-effect`. Do not promote at n=1.     |
| **Merged ≠ published**  | A merged PR changes what `main` says and nothing any user is running. Releasing is manual: bump `version` in **both** `package.json` and `public/manifest.json` (unlinked — they read 1.6.1 and 1.6.2 on 4 September 2026), check the Web Store dashboard for the published version, `npm run package`, upload `cc-checker-<version>.zip` by hand. Never write "shipped" for "merged".                                                                                                       |
| **Ticket key `CC-NNN`** | The key from Alex's own tracker for the two colour-contrast projects (`CC-001` to `CC-004` so far), shared with the sibling web app. Commit subjects are `<type>: CC-<n> - <gitmoji> Description`; branches are `<type>/CC-<n>[-short-slug]`. `feat/vite-migration` (merged 11 September 2026) carried no key — drift, left alone mid-flight (`docs/GIT.md`).                                                                                                                                |
| **Alex merges**         | Claude never merges a human PR and has no standing authority to; green Dependabot PRs are delegated (`docs/GIT.md` §Who merges, 11 September 2026). `enforce_admins` is off on `main`, so Alex's approval is his own button and his reading of the PR is the whole gate beyond the required `Lint, build, e2e` check. Which merge button is Alex's call per PR; rebase is the default since 13 September 2026 (`docs/GIT.md` §Merge strategy), and the history before that is merge commits. |

## Terms deliberately not defined here

Named with a re-entry condition, following nas-stacks' precedent of stating what was dropped rather
than porting it hollow.

| Term                                                                              | Why not                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Package, workspace, barrel export, changeset, public API, semver tooling          | Nothing is published to npm; the release is a zip and a dashboard. Re-entry: the day a Web Store upload is automated.                                                                                                                                                                   |
| Board, chunk, stage, `[GATE]` chunk, persona, ceremony, WIP limit                 | moe's build-plan and orchestration vocabulary. Work here is a `CC-NNN` ticket, a branch and a PR. Re-entry: if a `BUILD_PLAN.md`-shaped document ever appears.                                                                                                                          |
| Risk tier, Tier 0–3, track record, auto-merge, HITL                               | chief-clancy's and moe's autonomous-merge apparatus. Alex merges; there is no autonomy to gate. Re-entry: only if Claude is ever granted merge rights, which is not planned.                                                                                                            |
| Mutant, control run, mutation survival, `HUNG`                                    | Mutation-testing vocabulary from nas-stacks. ~~There are no unit tests to mutate; the suite is end-to-end.~~ The colour utilities got 22 Vitest cases on 17 September 2026, so the re-entry condition is met and adopting the gate is an open decision (`docs/TESTING.md` §Not ported). |
| Stack, Deploy, Periphery, dead-man's switch, hold-and-fire, teardown window       | nas-stacks' operational vocabulary for a running service. Nothing here runs anywhere but inside the user's browser.                                                                                                                                                                     |
| P1–P7 by number                                                                   | nas-stacks cites numbered principles from scripts. The disciplines that carried over ("go and look", "unexercised is not evidence", "merged is not deployed") are written as directives in `CLAUDE.md` instead. Re-entry: when a script or workflow needs to cite one by number.        |
| Copilot review, CodeRabbit                                                        | No bot reviewer is integrated; `copilot-surrogate` covers the reads-HEAD-not-diff scope in-chat. Re-entry: if one is enabled, its dispatch and triage mechanics go in `docs/DEVELOPMENT.md` §The review gate.                                                                           |
| APCA                                                                              | The `feat/CC-003-apca-3` branch is a separate experiment that has not merged. Re-entry: define it when it lands, from the code that lands.                                                                                                                                              |
| `browser.*` namespace, `safari-web-extension-converter`, `minimum_chrome_version` | Safari support is a stated goal with nothing started, and `minimum_chrome_version` is deliberately unset. Re-entry: when Safari work begins, from `docs/ARCHITECTURE.md` §Safari and other browsers.                                                                                    |
